# NS-ARS R5.1 — backup и rollback

Эта инструкция подготовлена заранее. Ни одна внешняя операция из неё не
выполнялась.

## Пакет до размещения

До первого hosted checkpoint сохранить в один датированный release record:

| Объект | Что фиксировать | Критерий пригодности |
| --- | --- | --- |
| Исходник | release fingerprint, lockfile, build/test receipt | хэш повторяется |
| Deployment | идентификатор текущего и нового checkpoint | оба доступны для выбора |
| D1 | полный remote export плюс список таблиц и количество строк | экспорт читается, хэш записан |
| R2 | inventory ключей, размеров, ETag/хэшей и отдельная копия объектов | число и объём совпадают |
| DNS | все записи `ns-ars.ru`, TTL и провайдер | прежние значения можно восстановить буквально |
| TLS/HTTP | сертификат, expiry, цепочка redirect, основные заголовки | baseline датирован |
| CMS | активная ревизия каждой из 9 страниц | pageId → revisionId записаны |

R2 сейчас зарезервирован и не содержит обязательных публичных медиа. Если на
content-freeze он останется пустым, это нужно явно записать как `EMPTY_VERIFIED`,
а не пропускать проверку.

## Порядок отката

Применять наименьший достаточный уровень.

1. **Одна страница:** в CMS переключить active pointer на последнюю известную
   исправную immutable revision; убедиться, что публичная страница читает её.
2. **Весь код:** вернуть предыдущий проверенный deployment checkpoint; D1 не
   перезаписывать, если схема совместима и данные исправны.
3. **Домен:** восстановить буквально сохранённые DNS-значения и TTL; проверить
   authoritative DNS, TLS и HTTP с независимой сети.
4. **Данные:** остановить запись, сохранить аварийный export повреждённого
   состояния, восстановить D1/R2 в отдельный ресурс, сравнить и только затем
   переключать binding. Не импортировать backup поверх единственной живой копии.

## Триггеры немедленного rollback

- HTTP 5xx на главной или двух и более зарегистрированных маршрутах;
- потеря D1 binding, отсутствие active revision или повреждённый JSON;
- admin bypass, утечка черновика или межсайтовая запись;
- неверный recipient формы или отправка без согласованного legal-контура;
- TLS-ошибка, redirect-loop или обслуживание неутверждённого origin;
- несоответствие release fingerprint;
- опубликованный материал без подтверждённых прав.

## Проверка после отката

- exact origin отвечает ожидаемым checkpoint и fingerprint;
- 9/9 маршрутов и 404 доступны;
- CMS read-only показывает ожидаемые active revision IDs;
- анонимный admin API закрыт;
- контакты и индексация остаются выключенными, если причина инцидента не
  устранена;
- инцидент и фактическое время восстановления занесены в release record.

## Владельцы решений

- переключение ревизии страницы: назначенный allowlisted CMS-администратор;
- rollback deployment: владелец hosting-проекта;
- DNS: владелец зоны `ns-ars.ru`;
- возврат индексации и форм: только после совместного технического и
  содержательного подтверждения.
