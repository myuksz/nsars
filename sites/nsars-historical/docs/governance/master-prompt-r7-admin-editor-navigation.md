# Мастер-промпт R7: отдельные экраны конструктора NS-ARS

## Роль

Ты — ведущий разработчик и QA-инженер русскоязычной CMS NS-ARS. Работаешь только с новым проектом `ns-ars.ru`. Ресурс `ns-ars-production.ru`, его поддомены, DNS, hosting, файлы, БД и настройки запрещено изменять.

## Исходный дефект

В опубликованном `/admin` левая навигация «Структура» реализована якорями одной длинной страницы. Нажатие, например, «Обложка» добавляет `#edit-hero` и только прокручивает документ. Все редакторские разделы остаются одновременно отрисованными. Это противоречит прямому требованию владельца.

## Цель R7

Переделать конструктор в двухуровневую рабочую поверхность:

1. верхний уровень выбирает самостоятельную страницу сайта;
2. левый уровень выбирает отдельный экран редактирования выбранной страницы;
3. центральная область показывает только один выбранный экран;
4. выбор экрана фиксируется в URL и восстанавливается после обновления, переходов «Назад/Вперёд» и прямого открытия ссылки.

## Обязательное поведение

- Канонический маршрут страницы конструктора: `/admin/pages/{pageId}/?section={sectionId}`.
- Допустимые `sectionId`: `page`, `hero`, `approach`, `process`, `media`, `directions`, `footer`.
- Неизвестный или отсутствующий `sectionId` безопасно заменяется на `page`.
- При переключении верхней вкладки сохраняется выбранный `sectionId`.
- При переключении левого пункта меняется URL без перезагрузки и без потери несохранённых данных.
- «Назад/Вперёд» между разделами одной страницы переключает экран без предупреждения о потере данных.
- Переход на другую страницу или в глобальный раздел при несохранённых данных сохраняет действующее предупреждение и варианты: сохранить, уйти без сохранения, остаться.
- В DOM центральной области одновременно присутствует ровно одна `.editor-section`.
- Левая навигация имеет семантику вкладок: `role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`; активная панель имеет `role="tabpanel"`.
- Глобальные экраны «Меню сайта» и «Медиатека» остаются самостоятельными маршрутами.
- Существующая модель данных, API, ревизии, публикация, видимость, медиатека и публичные страницы не изменяются.
- Не добавлять фиктивные кнопки, произвольный код, новую БД-миграцию или дублирующее хранилище.

## Защита от ложного исправления

Недостаточно:

- изменить только URL;
- скрыть остальные разделы CSS без изменения фактического UI-состояния;
- оставить якоря `#edit-*`;
- проверить только исходный код;
- считать успешный build доказательством поведения опубликованной версии.

## Реализация

1. Ввести единый типизированный реестр редакторских разделов и функцию нормализации `sectionId`.
2. Передавать нормализованный начальный раздел из серверного маршрута в клиентский редактор.
3. Синхронизировать выбранный раздел с `history.pushState` и `popstate`.
4. Генерировать ссылки страниц с сохранением текущего раздела.
5. Рендерить только активную панель.
6. Добавить автоматические контрактные тесты нормализации и ссылок.
7. Добавить проверку фактического рендера: после последовательного открытия всех семи разделов URL соответствует выбору, активен один tab и в центре существует одна `.editor-section`.

## Приёмка

R7 проходит только если:

- все 9 страниц открываются самостоятельными маршрутами;
- на каждой странице доступны 7 отдельных редакторских экранов;
- ни один пункт «Структуры» не использует hash-якорь;
- после перезагрузки остаётся выбранный экран;
- Back/Forward работает;
- в центре никогда не отображаются все разделы сразу;
- сохранение, preview, публикация и история версий не регрессировали;
- build, lint и тесты проходят;
- фактическая проверяемая сборка совпадает с исходным кандидатом R7.

## Граница выпуска

Сначала создать и проверить кандидат R7. Боевой выпуск на `https://ns-ars.ru` выполнять только через штатный Sites checkpoint/release-процесс и после выполнения его требований. Не затрагивать `ns-ars-production.ru` ни при каких обстоятельствах.
